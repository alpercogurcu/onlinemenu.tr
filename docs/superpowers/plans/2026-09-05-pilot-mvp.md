## Global Constraints

- Para birimi: tüm tutarlar **kuruş cinsinden int64**; float yasak. Yüzdeler `bps` (10000 = %100).
- KDV: `order_items.unit_price_amount` **KDV dahil** brüt fiyattır (Türkiye menü fiyatı). Vergi payı: `tax = gross - gross*10000/(10000+bps)`, tam sayı aritmetiği, yarım yukarı yuvarlama (`(gross*bps + (10000+bps)/2) / (10000+bps)`).
- Zaman aralığı yarı açık `[from, to)`; `from < to`; en fazla 92 gün. Gün kovalaması `(ts AT TIME ZONE $tz)::date`, `tz` varsayılanı `Europe/Istanbul`, `time.LoadLocation` ile doğrulanır.
- Modül izolasyonu: `pos` yalnız `payment/public` import eder; `pool.Query/Exec` modül kodunda yasak; her okuma `WithTenantReadTx`.
- Yetki: yeni OPA aksiyonu `pos.report.read` → `shift_manager` (manager wildcard'dan geçer). Seed'deki `reports:read` bu aksiyona bağlanır; `permission_wiring_test.go` registry'si güncellenir.
- Handler hata gövdesi: mevcut `respondError(w, status, code, msg)` deseni (pos ve payment http paketlerinde).
- Kod/yorum İngilizce; commit mesajı Türkçe `tip(alan): açıklama`, **AI attribution/Co-Authored-By footer'ı yok**, push yok.
- Komutlar `task` üzerinden: `task backend:test:unit`, `task backend:test:integration`, `task backend:lint`, `task web:typecheck`, `task web:lint`, `task web:test` (Task 1'de eklenir). Go testleri `backend/` dizininden `go test ./internal/...` ile de koşturulabilir (task altında aynı komut).
- Frontend: yeni bileşen önce `web/packages/ui-kit`'e değil, admin'e özel olduğu için `web/apps/admin` altında kalır (dashboard bileşenleri admin'e özgü).
- Testler: Go tablo-driven + testcontainers integration; admin vitest + RTL, `@/lib/api` mock deseni `web/apps/admin/src/test/use-order-details.test.tsx`'teki gibi.

### Rulings (plan yazımında verilen kararlar)

- **R1** Rapor ucu `pos` modülünde: `GET /api/v1/pos/reports/sale-details`. Ödeme kırılımı `paymentpub.SalesSummaryReader` (yeni, dar) üzerinden. Gerekçe: satış verisi (checks/orders/items) pos'ta; tek çağrı yönü zaten pos→payment. Yanlışsa maliyet: ileride `reports` modülüne taşımak iki dosya kaydırmaktır.
- **R2** "Satış" = pencere içinde **kapanan** adisyonların (`checks.status='closed'`, `closed_at ∈ [from,to)`) aktif (rejected/cancelled olmayan) siparişlerinin kalem toplamı. "İptal" ayrı akümülatör: pencere içinde `cancelled` olan adisyonların aynı hesabı. İade kavramı pos'ta yok; ödemede `voided` ayrı sayılır.
- **R3** Business-day ofseti (ADR-DATA-003 taslak, `branch_settings.business_day_offset` okunmuyor) **uygulanmaz**; istemci takvim günü sınırlarını gönderir. Yanlışsa maliyet: pilot müşteri gece 04:00 vardiya kesimi isterse `from/to` sunucuda kaydırılır, API şekli değişmez.
- **R4** Kuruş yuvarlama (backlog 3) ertelenir: tutarlar zaten tam kuruş, kupür yuvarlaması pilotta istenmedi.
- **R5** Vardiyaya otomatik katılım (backlog 3) ürün kararı, bu planda yok.
- **R6** Alertmanager kurulmaz; metrik + Prometheus rule dosyası eklenir, bildirim kanalı kullanıcı kararı.
- **R7** Keycloak SMTP: realm JSON'a `smtpServer` bloğu `${env.SMTP_*}` yer tutucularıyla girer; implementer Keycloak 26 realm import'unun `${env.X}` çözdüğünü context7 ile doğrular, çözmüyorsa README'de Admin Console adımı ile belgelenir ve compose'a env geçirilir.

TanStack `useQueries` ile her 100'lük dilimi ayrı query yapmak "yeni gelen tek id için yalnız onu iste" şartını sağlamaz; bu yüzden hook kendi `useRef` defterini tutar:

```ts
const ORDER_DETAILS_BATCH = 100

// useOrderDetails resolves order details for a live board in batches, so a
// kitchen display with N tickets makes ceil(N/100) requests instead of N.
// It keeps its own ledger (ref) of ids already asked for — including ids the
// backend never returned, which are not asked again — so a newly arrived
// ticket costs exactly one request carrying only that id.
export function useOrderDetails(ids: string[]): Map<string, Order> {
  const [details, setDetails] = useState<Map<string, Order>>(() => new Map())
  const requested = useRef<Set<string>>(new Set())
  const idsKey = ids.join(",")

  useEffect(() => {
    const pending = ids.filter((id) => !requested.current.has(id))
    for (const id of pending) requested.current.add(id)

    // Drop tickets that left the board so the map never grows unbounded.
    setDetails((prev) => {
      const keep = new Set(ids)
      let changed = false
      const next = new Map<string, Order>()
      for (const [id, order] of prev) {
        if (keep.has(id)) next.set(id, order)
        else changed = true
      }
      return changed ? next : prev
    })

    if (pending.length === 0) return
    let cancelled = false
    const batches: string[][] = []
    for (let i = 0; i < pending.length; i += ORDER_DETAILS_BATCH) {
      batches.push(pending.slice(i, i + ORDER_DETAILS_BATCH))
    }
    void Promise.all(
      batches.map((batch) =>
        api.get<Order[]>("/api/v1/pos/orders", { params: { ids: batch.join(",") } }).then(({ data }) => data ?? []),
      ),
    ).then((results) => {
      if (cancelled) return
      setDetails((prev) => {
        const next = new Map(prev)
        for (const order of results.flat()) next.set(order.id, order)
        return next
      })
    })
    return () => {
      cancelled = true
    }
    // idsKey is the stable identity of `ids`; the array itself is rebuilt each render.
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [idsKey])

  return details
}
```

Gerekli import'lar: `useEffect, useRef, useState` from `react`. Test `Promise.all` sonucunu `waitFor` ile bekliyor; istek hatası durumunda id `requested`'ta kalır (tekrar denenmez) — bu bilinçli: KDS WebSocket'i zaten yeniden bağlanınca snapshot getirir.
